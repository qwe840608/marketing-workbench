# セルフホストする人のためのコンプライアンスの注意事項

> **言語 / Language / 語言 / 语言**：[繁體中文](合規須知.md) | [简体中文](合规须知.md) | [English](compliance-notes.md) | 日本語

このワークベンチをセルフホストすると、あなた自身が自分の Meta、Google、TikTok アプリの**開発者**になります。各プラットフォームの規約上の義務を負うのはあなたであり、このプロジェクトではありません。このリストは、セルフホストの前後に自分で済ませておくべきことをまとめたものです。各規定の出典と確認日は [`プラットフォームポリシー.md`](プラットフォームポリシー.md)（プラットフォームポリシー）をご覧ください。

> この文書はプラットフォームの規定とワークベンチ側の対応をまとめたもので、法的助言ではありません。規約は改訂されるため、公式の最新文書を優先してください。

## まず用途を確認：自分または自社ブランドだけで使う

ワークベンチは **1 つのブランドを、ブランドの所有者が自分でセルフホストし、自分のアカウントを管理する**ことを前提に設計されています。次の用途はサポート対象外で、プラットフォームの規定に違反するおそれもあります。

- **運用代行**：クライアントや他社に代わってそのアカウントを管理すること。Meta では、アプリの役割を持たない人に使わせるには App Review を通過して高度なアクセス権限を取得し、ビジネス認証を完了する必要があります。TikTok は「自分またはチームが管理するアカウントにコンテンツをアップロードするツール」を受け付けないと明記しています。
- **複数ブランド**：1 つのワークベンチで別々の主体（別の会社）のブランドを管理すること。現在はサポートしていません。
- **公開サービス**：他の人が登録して使えるようにすること。

同じブランドのチームメンバーがそれぞれワークベンチにログインするのは問題ありません。プラットフォームが見るのは「誰がアプリを認可したか」だけで、その人はあなたの Meta アプリで役割（管理者、開発者、テスター）を持っている必要があります。アプリはブランドを所有する主体の名義で作成してください。個人ブランドなら個人アカウントで、会社のブランドなら会社が作成し、従業員個人の開発者アカウントは使わないでください。

## 1. プライバシーポリシーと利用規約（すべてのプラットフォームで必要）

自分のウェブサイトに公開ページを 2 つ用意し、その URL を各プラットフォームの管理画面に入力します。テンプレートは [`templates/`](templates/) にあります。`{{…}}` を自分の情報に置き換え、使っていない段落は削除してください。テンプレート、あなたの `.env` の設定、この注意事項を自分の AI に渡し、実際の設定に合わせて書いてもらうこともできます。

ポリシーの内容は実際の設定どおりに書く必要があり、少なくとも次を含めてください。

- 取得するデータ：自分のアカウントの投稿と成果、**他の人があなたの投稿に付けた公開コメント**（名前、アカウント識別子、内容）。
- 委託先：TypeSafe（コメント分類）、あなたが設定した AI サービス、接続した AI エージェント、LINE（緊急通知）。使っていないものは削除します。
- 保存期間：コメントは取得から `COMMENT_RETENTION_DAYS` 日（既定は 365）。YouTube データの 30 日ルール。
- 削除依頼：コメント投稿者は削除を依頼でき、7 日以内に対応します。
- YouTube が求める内容：YouTube API サービスを使っていることの説明、[Google プライバシーポリシー](https://policies.google.com/privacy) と認可の取り消しページ `https://security.google.com/settings/security/permissions` へのリンク。
- 利用規約には「ユーザーは [YouTube 利用規約](https://www.youtube.com/t/terms) に拘束されることに同意する」と明記します。

## 2. 各プラットフォームの管理画面の設定

### Meta（Facebook／Instagram／Threads）

- アプリ名にプラットフォーム名を含めたり、Meta と提携していると誤解させたりしてはいけません。
- 「ベーシック」にプライバシーポリシーの URL、利用規約の URL、データ削除手順の URL（例：`/privacy#delete`）を入力します。
- 自分だけで使う場合は**標準アクセス**で十分で、App Review は不要です。認可する人はアプリで役割を持っている必要があります。Threads アカウントはテスターとして追加し、Threads 側で招待を承認してください。
- 標準アクセスのみでは Instagram のコメント Webhook は届きません（Live モード＋高度なアクセスが必要）。ワークベンチは定期的な API 取得に切り替えるため、利用には影響しません。
- 権限を 28 日を超えて使わないと、Meta がその権限を無効にすることがあります。

### Google（YouTube）

- 同意画面の公開ステータスは**本番環境（In production）**に変更してください。「テスト中」のままだと refresh token が 7 日で切れ、YouTube を毎週連携し直すことになります。
- 個人利用で 100 人以下なら Google の確認申請は不要です。認可時に「確認されていないアプリ」の警告が出ますが、「続行」を押せば進めます。100 人を超える場合だけ確認が必要です。
- 「ブランディング」にアプリのホームページ、プライバシーポリシー、利用規約の URL を入力します。
- ワークベンチが求めるのは `youtube.readonly`、`yt-analytics.readonly`、`youtube.upload` だけです。より広いスコープを自分で追加しないでください。

### TikTok

- アプリ名に**「TikTok」を含めてはいけません**。自分のウェブサイト名と一致させ、機能の説明だけの名前にしないでください。
- ワークベンチが使えるのは **Sandbox** だけです。動画は下書きとしてあなたの TikTok に送られ（受信トレイに通知）、アプリ内で本文を補って投稿します。受信トレイ API は本文を受け付けず、カバー画像も選べません。
- Sandbox の公式な位置づけはテスト環境です（ターゲットアカウントは最大 10 個）。本番用途として長期間使うことは明文で認められておらずグレーゾーンなので、ご自身で判断してください。
- 直接投稿（`video.publish`）は審査前だと「自分のみ」しか選べず、投稿するアカウントは非公開アカウントである必要があります。審査は自分のアカウントを管理するツールを受け付けません。コメントの取得には法人として TikTok API for Business に申請する必要があり、ワークベンチは TikTok のコメントを取得しません。
- ツールを紹介するときは機能の説明（例：「公式 API で TikTok の下書きに送る」）にとどめ、TikTok との提携や公認を受けているように言わないでください。

### LINE

- 自分のグループへの通知にだけ使います。Push メッセージには月間の上限があるため、先にプランを確認してください。

## 3. AI とデータ処理者

- クラウドのモデルに送るテキストは、先に `redact.py` で個人情報をマスクします。オフにしないでください。
- **Gemini は有料枠のみ**：Gemini API の無料枠は送信された内容を Google の製品改善に使うため、サービスプロバイダーに対する Meta の要件に反します。そのためワークベンチは既定で Gemini にプラットフォームのデータを処理させず、Google Cloud プロジェクトに請求先を設定してから `GEMINI_PAID_TIER=true` にします。Anthropic と OpenAI の API は既定で API データを学習に使わないため、追加の設定は不要です。
- **個人向けサブスクリプションでログインするエージェントは学習をオフに**：エージェントが MCP 経由で読んだコメントは会話に入ります。エージェントが個人向けサブスクリプション（Claude Pro／Max 上の Claude Code、ChatGPT Plus など）でログインしている場合は、そのサービスのプライバシー設定で「会話をモデルの学習に使う」をオフにしてください。API キーを使うエージェントなら不要です（Gemini は引き続き有料枠が必要）。
- Meta は、サービスプロバイダーがあなたの指示にのみ従ってデータを処理することに**書面で**同意するよう求めています。必要に応じて、TypeSafe などのプロバイダーにデータ処理契約（DPA）を依頼してください。

## 4. デプロイ後にすること

1. データ保持で削除される件数をプレビューします（読み取りのみ）：`uv run --project backend python scripts/data_retention.py`。
2. 確認したら毎日の削除を有効にします：同じコマンドに `--enable` を付けます。
3. コメント投稿者から削除依頼を受けたら：`--find-commenter` で該当者を探し、`--delete-contact` でプレビューし、確認後に `--apply` を付けて削除します。
4. 「連携を解除」は認可を取り消し、そのプラットフォームで同期済みのデータ（YouTube、TikTok）を削除します。プラットフォーム上のコンテンツには影響しません。
5. ワークベンチの画面はローカルとプライベートネットワーク（Tailscale）にのみ公開し、画面を直接インターネットに公開しないでください。公開される入口は、署名を検証する Webhook と期限付きのメディアリンクだけです。
6. セキュリティインシデント（PC やアカウントへの侵入）が起きたら、まず各プラットフォームの連携を解除してキーを変更します。TikTok の規約は、直ちに接続を切断して報告することを求めています。

## 5. オープンソースライセンスと TikTok

ワークベンチは HTTP で各プラットフォームの公式 API を呼び出すだけで、TikTok の SDK やサンプルコードを含んでいません。そのため、TikTok 開発者規約 III.3.e（TikTok 開発者サービスをオープンソースライセンスの義務に服させてはならない）が、このプロジェクトのライセンスによって影響を受けることはありません。自分のフォークにプラットフォームの SDK を加える場合は、ライセンスの互換性をご自身で確認してください。
