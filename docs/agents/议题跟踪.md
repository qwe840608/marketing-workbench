# Issue tracker：GitHub

> **语言 / Language / 語言 / 言語**：[繁體中文](議題追蹤.md) | 简体中文 | [English](issue-tracker.md) | [日本語](Issueトラッカー.md)

本 repo 的 issue 与规格以 GitHub issue 的形式存放。所有操作都使用 `gh` CLI。

## 惯例

- **创建 issue**：`gh issue create --title "..." --body "..."`。多行内容使用 heredoc。
- **读取 issue**：`gh issue view <number> --comments`，用 `jq` 过滤评论，并一并获取标签。
- **列出 issue**：`gh issue list --state open --json number,title,body,labels,comments --jq '[.[] | {number, title, body, labels: [.labels[].name], comments: [.comments[].body]}]'`，搭配适当的 `--label` 与 `--state` 过滤条件。
- **在 issue 下评论**：`gh issue comment <number> --body "..."`
- **添加／移除标签**：`gh issue edit <number> --add-label "..."` / `--remove-label "..."`
- **关闭**：`gh issue close <number> --comment "..."`

从 `git remote -v` 推断 repo；在克隆的仓库内执行时，`gh` 会自动完成这一点。

## 把 Pull request 当作分类入口

**PR 作为请求入口：否。**_（如果本 repo 把外部 PR 当作功能请求，设为 `yes`；`/triage` 会读取这个标记。）_

设为 `yes` 时，PR 使用与 issue 相同的标签与状态，改用对应的 `gh pr` 命令：

- **读取 PR**：`gh pr view <number> --comments`，用 `gh pr diff <number>` 查看 diff。
- **列出待分类的外部 PR**：`gh pr list --state open --json number,title,body,labels,author,authorAssociation,comments`，然后只保留 `authorAssociation` 为 `CONTRIBUTOR`、`FIRST_TIME_CONTRIBUTOR` 或 `NONE` 的（去掉 `OWNER`/`MEMBER`/`COLLABORATOR`）。
- **评论／标签／关闭**：`gh pr comment`、`gh pr edit --add-label`/`--remove-label`、`gh pr close`。

GitHub 的 issue 与 PR 共用同一套编号，所以单独的 `#42` 可能是其中任一种：先用 `gh pr view 42` 判断，不是的话再用 `gh issue view 42`。

## 当 skill 说“publish to the issue tracker”（发布到 issue tracker）

创建一个 GitHub issue。

## 当 skill 说“fetch the relevant ticket”（获取相关 ticket）

运行 `gh issue view <number> --comments`。

## Wayfinding 操作

供 `/wayfinder` 使用。**map** 是单一 issue，以 **child** issue 作为 ticket。

- **Map**：一个带有 `wayfinder:map` 标签的 issue，正文包含 Notes / Decisions-so-far / Fog。`gh issue create --label wayfinder:map`。
- **Child ticket**：以 GitHub sub-issue 关联到 map 的 issue（用 `gh api` 调用 sub-issues 端点）。未启用 sub-issues 时，把 child 加到 map 正文的任务列表中，并在 child 正文顶部写上 `Part of #<map>`。标签：`wayfinder:<type>`（`research`/`prototype`/`grilling`/`task`）。被认领后，ticket 指派给负责推进的开发者。
- **Blocking**：GitHub 的**原生 issue 依赖关系**，这是标准且在 UI 上可见的表示方式。用 `gh api --method POST repos/<owner>/<repo>/issues/<child>/dependencies/blocked_by -F issue_id=<blocker-db-id>` 添加一条依赖，其中 `<blocker-db-id>` 是阻塞方的数字**数据库 id**（`gh api repos/<owner>/<repo>/issues/<n> --jq .id`，_不是_ `#number` 或 `node_id`）。GitHub 会报告 `issue_dependencies_summary.blocked_by`（只计尚未关闭的阻塞方，即实时的闸门）。无法使用依赖关系时，退而在 child 正文顶部写一行 `Blocked by: #<n>, #<n>`。当所有阻塞方都关闭时，该 ticket 即解除阻塞。
- **Frontier 查询**：列出 map 中尚未关闭的 child（`gh issue list --state open`，范围限定在 map 的 sub-issues／任务列表），去掉有未关闭阻塞方（`issue_dependencies_summary.blocked_by > 0`，或 `Blocked by` 行中有未关闭的 issue）或已有指派人的，按 map 中的顺序取第一个。
- **认领**：`gh issue edit <n> --add-assignee @me`，这是该会话的第一次写入。
- **解决**：`gh issue comment <n> --body "<answer>"`，然后 `gh issue close <n>`，再在 map 的 Decisions-so-far 中追加一条上下文指引（要点＋链接）。
