# AI エージェント向けプラットフォーム連携ガイド（ブラウザー操作）

> **言語 / Language / 語言 / 语言**：[繁體中文](../zh-tw/agent平台串接引導.md) | [简体中文](../cn/agent平台对接引导.md) | [English](../en/agent-platform-setup-guide.md) | 日本語
>
> **エージェントへ：始める前に、ユーザーの言語を判断してください**（ユーザーが送ってきたメッセージから。まだ何も書いていなければシステムの言語設定から）。日本語でなければ、上の該当する言語版を読んでその手順に従い、最後までその言語でユーザーと話してください。4 言語のどれにも当てはまらない場合は English 版に従い、返答はユーザーの言語で行います。

この文書は **AI エージェント**向けに書かれています。ユーザーがワークベンチを初めて構築したあと、Facebook ページ、Instagram、Threads、YouTube、TikTok を連携するには、まず各プラットフォームの**開発者向け管理画面**で自分のアプリを作成する必要があります。手順が煩雑なので、あなたがブラウザーを操作して設定を代わりに入力し、ユーザーは本人がしなければならない部分だけを行います。

- 前提：[`エージェント向けインストールガイド.md`](エージェント向けインストールガイド.md)（AI エージェント向けインストールガイド）のステージ 1–5 が完了していること（ワークベンチを内部 https URL で開けて、プライバシーポリシーと利用規約が公開済み）。
- ブラウザーを操作できる場合（Claude in Chrome、Claude の内蔵ブラウザー、Codex のブラウザーツールなど）はこの文書に従ってください。操作できない場合は、同じ手順を文章で一歩ずつ案内し、ユーザー自身にクリックしてもらいます。
- 手順はワークベンチの「設定 → プラットフォーム連携 → 設定ガイド」と同じです（出典は `frontend/src/platformGuides.ts` で、管理画面の実際の表記を使っています）。権限は `backend/app/services/oauth.py` を正とし、規定と出典は [`プラットフォームポリシー.md`](プラットフォームポリシー.md)（プラットフォームポリシー）にあります。3 つが食い違う場合はプログラムを正とし、メンテナーに報告してください。

## 境界線（必ず守ること）

してよいこと：開発者向け管理画面内の移動、クリック、**機密でない**項目の入力（アプリ名、ユースケース、コールバック URL、権限、scopes、API の有効化、ブランド名と連絡先メール、カテゴリ、説明、プライバシーポリシーと利用規約の URL）、「保存」を押すこと。

してはいけないこと：

1. **ログイン、パスワード、2FA、セキュリティ確認**は必ずユーザー本人が入力します。ログインページや「パスワードを入力してください」が出たら止まって本人に操作してもらい、終わってから続けます。
2. **シークレットに触れない**：app secret／Client secret の「表示」を押さない、コピーしない、読み上げない、会話やファイルに書かない、シークレットが写った画面をスクリーンショットしない。アプリ ID とシークレットはユーザー本人がワークベンチの「設定 → プラットフォーム連携」の該当カードに貼り付けます（暗号化して保存されます）。会話には貼らないでください。
3. **ワークベンチの「〇〇 アカウントを連携」を押さない。OAuth の認可／同意画面を代わりに押さない**。開発者規約への同意も代行しません（例：TikTok の「Target Users」でのログインと同意）。
4. **審査申請や公開モードの変更をしない**：Meta App Review やビジネス認証、Google のアプリ確認、TikTok の Production 審査を申請しないでください。Meta アプリを Live に切り替えないでください。TikTok の Direct Post はオフのままにします。
5. **投稿しない、コメントに返信しない、送信や投稿のスイッチをオンにしない**。ウェブページのスクレイピングや非公式 API も使いません。ブラウザーは開発者向け管理画面の設定ページだけに使います。
6. **リソースを作成したり規約に同意したりするボタンは先に聞く**（アプリを作成、Google Cloud プロジェクトを作成、Google の「アプリを公開」）。ユーザーが同意してから押します。
7. **画面がこの文書と違うときは推測しない**：管理画面はよく変わります。まずスクリーンショットをユーザーに見せて違いを説明し、必要なら公式ドキュメントを確認してから次の手順を決めます。
8. **用途が合わなければ止まる**：クライアントのアカウントの運用代行、別々の会社の複数ブランドの管理、他の人への登録開放を望む場合は、サポート対象外でプラットフォームの規定に違反するおそれがあることを説明し（[`コンプライアンスの注意事項.md`](コンプライアンスの注意事項.md)（コンプライアンスの注意事項）参照）、ユーザーに判断してもらいます。

## 始める前に

1. 新しいタブで作業し、ユーザーがもともと開いているタブには触れません。
2. 設定するプラットフォームを聞き、アカウントの種類を確認します。Facebook は**ページの管理者**であること。Instagram は**プロアカウントで、そのページにリンクされている**こと。Threads は個人アカウントで構いません。YouTube はチャンネルを所有する Google アカウントを使います（ブランドチャンネルならブランド アカウントを選択）。TikTok は個人アカウントで構いません。
3. **コールバック URL** を取得します。ユーザーにワークベンチの「設定 → プラットフォーム連携」を開いてもらい、該当プラットフォームのカードの「設定ガイド」でコピーボタンを押して貼ってもらいます（コールバック URL は機密ではありません）。あなたがブラウザーでそのウィンドウを開いて読んでも構いません。形式は `<内部 https URL>/api/oauth/<meta|threads|youtube|tiktok>/callback` です。`https://` で始まっていなければ、いったん止まります。ワークベンチは内部 https URL で開かないと連携できません。
4. **プライバシーポリシーと利用規約の公開 URL** を用意します（TikTok の Sandbox でも必須）。
5. **アプリ名**にはユーザーのウェブサイト名またはブランド名を使います（例：「〈ブランド〉 Workbench」）。TikTok、Facebook、Instagram などのプラットフォーム名を含めてはならず、機能の説明だけの名前も避けてください。

1 つの手順を終えるたびにスクリーンショットで確認し、何をしたかをユーザーに一言伝えます。コールバック URL と権限は一字一句照合してください。

## Meta（Facebook ページ＋Instagram）

管理画面：<https://developers.facebook.com/apps/>

1. （先に聞く）<https://developers.facebook.com/apps/creation/> で「アプリを作成」。名前はブランド名にします。ユースケースは Facebook ページに関する項目を選び、あとは「次へ」で進めます。
2. 「アプリの設定 → ベーシック」：プライバシーポリシーの URL、利用規約の URL、データ削除手順の URL（プライバシーポリシーの `#delete` を指定可）、カテゴリ、連絡先メールを入力して保存します。アプリ ID と app secret は、ユーザー本人にワークベンチの Meta カードの「アプリ ID」と「アプリシークレット」へ貼ってもらいます。
3. 「Facebook ログイン → 設定」（ユースケースから作成した場合は「ビジネス向け Facebook ログイン → 設定」）の「有効な OAuth リダイレクト URI」に meta のコールバック URL を貼り付け、「変更を保存」を押します。
4. 「ユースケース → カスタマイズ → アクセス許可と機能」で、次の権限を 1 つずつ探して「追加」を押します（一括追加の機能はないので、ページ内検索を使えます）：`pages_show_list`、`pages_read_engagement`、`pages_read_user_content`、`pages_manage_metadata`、`pages_manage_posts`、`read_insights`。任意：`pages_manage_engagement`（動画のカスタムカバー用。ない場合はカバー機能だけが無効になります）。
5. Instagram を使う場合：同じページで `instagram_basic`、`instagram_manage_comments`、`instagram_manage_insights`、`instagram_content_publish` も追加します。同じページで見つからない場合は「ユースケース」で「Instagram のメッセージとコンテンツを管理」を追加し、「Facebook ログインによる API 設定」を選んでから追加します。
6. ユーザーに引き継ぐ：ワークベンチで「Meta アカウントを連携」を押し、認可画面の「設定を編集」（または「アクセスを編集」）で Facebook ページと Instagram にチェックを入れてもらいます。

自分だけで使う場合は標準アクセスで十分で、**審査申請は不要**です。連携する人はアプリで役割を持っている必要があります。

### Meta Webhook（任意。ngrok を先に済ませ、WEBHOOK_PUBLIC_URL が設定されていること）

1. 認証トークンはユーザー本人がワークベンチの Meta カードの「手動設定（詳細）→ Webhook 検証トークン」で設定し、管理画面にも本人が入力します。あなたは扱いません。
2. 管理画面左側の「Webhooks」で「Page」を選び →「このオブジェクトにサブスクライブ」。コールバック URL に `<WEBHOOK_PUBLIC_URL>/webhook/meta-inbound` を入力します。ユーザーがトークンを入力したら「確認して保存」を押します。フィールドは「feed」をサブスクライブします。Instagram を使う場合は「Instagram」オブジェクトに切り替え、同じ URL とトークンで「comments」をサブスクライブします。
3. 伝えること：開発モードで届くのはテストイベントと、役割を持つ人自身のコメントだけです。Instagram のコメント Webhook には Live＋高度なアクセスが必要で、今回の範囲外です。Webhook がなくても、ワークベンチは 1 時間ごとに自分で取得します。

## Threads（同じ Meta アプリ）

1. アプリを開き →「ユースケース」に「Threads API にアクセス」を追加 →「カスタマイズ → 設定」。
2. 「Threads アプリ ID」と「Threads app secret」（Facebook のものとは別）は、ユーザー本人にワークベンチの Threads カードへ貼ってもらいます。
3. 同じページの「リダイレクトコールバック URL」に threads のコールバック URL を貼り付けて保存します。認可解除／削除のコールバックが必須の場合は、何を入力するかを先にユーザーに聞きます（プライバシーポリシーの URL を使えます）。
4. 「アクセス許可と機能」で次を 1 つずつ追加します：`threads_content_publish`、`threads_manage_replies`、`threads_manage_insights`、`threads_read_replies`（`threads_basic` は最初から追加されています）。
5. 「アプリの役割 → 役割 → ユーザーを追加」で「Threads テスター」を選び、ユーザーから聞いた Threads のユーザーネームを入力します。
6. ユーザーに引き継ぐ：スマートフォンの Threads アプリで「設定 → アカウント → ウェブサイトのアクセス許可 → 招待」を開いて「承認」をタップし、ワークベンチで「Threads アカウントを連携」を押してもらいます。

## YouTube（Google Cloud）

1. （先に聞く）<https://console.cloud.google.com/projectcreate> でプロジェクトを作成します。名前は自由です。上部でこのプロジェクトが選択されていることを確認します。
2. 2 つの API を有効にします（どちらも「有効にする」を押す）：[YouTube Data API v3](https://console.cloud.google.com/apis/library/youtube.googleapis.com)、[YouTube Analytics API](https://console.cloud.google.com/apis/library/youtubeanalytics.googleapis.com)。
3. [ブランディング](https://console.cloud.google.com/auth/branding)で「開始」を押します：アプリ名、ユーザーサポートメール。「対象」は「外部」を選びます。連絡先メール。同意のチェックを入れる前に先に聞き、それから「作成」を押します。ホームページ、プライバシーポリシー、利用規約の URL も入力できます。
4. （先に聞く）[対象](https://console.cloud.google.com/auth/audience)で「アプリを公開」を押して「本番環境」にします。そうしないと認可が 7 日ごとに切れます。これは確認申請**ではありません**。100 人以下の自分用なら確認は不要なので、「確認のために送信」のようなボタンは押さないでください。
5. [データアクセス](https://console.cloud.google.com/auth/scopes)→「スコープの追加または削除」→「スコープを手動で追加」に 3 行を貼り付け、「テーブルに追加」→「更新」→「保存」を押します：
   - `https://www.googleapis.com/auth/youtube.readonly`
   - `https://www.googleapis.com/auth/yt-analytics.readonly`
   - `https://www.googleapis.com/auth/youtube.upload`

   `youtube` や `youtube.force-ssl` は追加しないでください。
6. [クライアントを作成](https://console.cloud.google.com/auth/clients/create)で「ウェブ アプリケーション」を選び、「承認済みのリダイレクト URI」に youtube のコールバック URL を貼り付けて「作成」を押します。
7. **すぐに手を止める**：シークレットはこのときしか表示されません。ユーザー本人に「クライアント ID」と「クライアント シークレット」をワークベンチの YouTube カードへ貼ってもらい（先に「JSON をダウンロード」で控えを保存しても構いません）、ダイアログを閉じてからスクリーンショットや操作を再開します。
8. ユーザーに引き継ぐ：ワークベンチで「YouTube アカウントを連携」を押してもらいます。「このアプリは Google で確認されていません」と表示されたら、本人が「詳細 →（アプリ名）に移動」を押し、権限はすべて許可します。

## TikTok（Sandbox のみ）

管理画面：<https://developers.tiktok.com/>（右上の「Developer Portal」）

1. （先に聞く）アプリを作成します。名前に**「TikTok」を含めてはならない**ので、ブランド名を使います。
2. ページ上部で「Sandbox」に切り替えて 1 つ作成します。
3. 「Add products」で **Login Kit** と **Content Posting API** を追加します。**Direct Post はオフのまま**にします。
4. Login Kit の「Redirect URI」で Web を選び、tiktok のコールバック URL を貼り付けます。
5. 「Scopes」の「Add scopes」で次の 4 つにします：`user.info.basic`、`user.info.stats`、`video.list`、`video.upload`。`video.publish` は追加しないでください。
6. Basic information の必須項目：App icon（画像ファイルはユーザーに用意してもらう）、Category、Description（事実どおりに。例：「自分の動画を TikTok の受信トレイに送り、自分のアカウントの公開動画のデータを取得する」）、利用規約とプライバシーポリシーの URL。「Apply changes」を押し、赤字が出なければ完了です。「Verify domains」は押す必要はありません。
7. ユーザーに引き継ぐ：「Target Users」→「Add account」で、本人が TikTok にログインして開発者規約に同意します（表示まで最大 1 時間かかる場合があります）。
8. ユーザーに引き継ぐ：Sandbox の「Credentials」にある Client key と Client secret を本人がワークベンチの TikTok カードに貼り、「TikTok アカウントを連携」を押します。

**絶対にしないこと**：Production 審査の申請（TikTok は私的・自分用のツールを受け付けません）、Direct Post のオン、TikTok API for Business の申請（法人のみ受付）。ユーザーに伝えること：動画は受信トレイの下書きにしか届きません（24 時間以内に保留中は最大 5 本）。本文とカバー画像はアプリ内で設定し、投稿時は「全員」を選び、その後ログインしていないブラウザーで公開されていることを確認します。

## 仕上げ

各プラットフォームが終わったら、ユーザーに次を一覧で伝えます：設定したコールバック URL、追加した権限、本人がまだ行うこと（シークレットの貼り付け、連携ボタン、招待の承認、Target Users）。ワークベンチのカードにアカウント名と「連携済み」が表示されれば完了です。カードに権限不足と表示された場合は、管理画面で補ってから、もう一度連携してもらいます。

よくあるエラー：

- 「URL が一致しません」／`redirect_uri_mismatch`：コールバック URL は丸ごと貼り付けます。スラッシュを増やしたり http に変えたりしないでください。
- 認可時に Facebook ページが見つからない：認可画面の「設定を編集」でチェックを入れます。また、本人がそのページの管理者である必要があります。
- Threads でテスターではないと表示される：Threads アプリで招待を承認します。
- 「連携」ボタンがグレーになっている：内部 https URL でワークベンチを開き直します。
- TikTok の「Apply changes」で赤字が出る：App icon、Category、Description、2 つのポリシー URL はすべて必須で、名前に TikTok を含めることはできません。
