この文書は **AI エージェント**（Claude Code や Codex など、ユーザーのパソコンでファイルを読みコマンドを実行できるエージェント）向けに書かれています。ユーザーがこの文書をあなたに渡し、**ワークベンチの構築を一歩ずつ一緒に進める**よう頼んでいます。ユーザーはエンジニアとは限りません。コマンドの実行と結果の確認はあなたが行い、平易な言葉で説明してください。本人が操作する手順では、どこをクリックし、何を貼り付けて返せばよいかを具体的に伝えてください。

始める前に [`コンプライアンスの注意事項.md`](コンプライアンスの注意事項.md)（コンプライアンスの注意事項）を読んでください。この文書は手順だけを扱います。プラットフォームの規定と公式出典は [`プラットフォームポリシー.md`](プラットフォームポリシー.md)（プラットフォームポリシー）に、詳しい運用手順は [`デプロイと運用.md`](デプロイと運用.md) にあります。

以下の画面名は日本語の画面表示に合わせています。

## エージェントが必ず守るルール

1. **秘密情報はローカルの `.env` にだけ置く**：キー、トークン、パスワードを会話に貼るよう頼まない、画面に表示しない、ログに書かない、git にコミットしない。ユーザーにキーが必要なときは本人に `.env` へ貼ってもらうか、あなたがローカルでファイルに書き込み、値は表示しないでください。
2. **パスワードは本人が入力する**：管理者パスワード、各プラットフォームへのログイン、認可の同意画面は必ずユーザー本人が操作します。代わりに入力したりクリックしたりしないでください。
3. **プラットフォームに何も送信しない**：構築中は投稿、コメント返信、送信スイッチのオンをしないでください。投稿はワークベンチの確認ダイアログでユーザーが押したときだけ行われます。
4. **各手順は「説明、実行、確認」の順で**：何を、なぜ行うかを一言二言で説明し、実行後に結果を確認し、成功してから次へ進みます。
5. **ソフトのインストール、アカウント作成、同意の前にユーザーに聞く**：たとえば winget で Node.js を入れる、ngrok に登録するなども、先に同意を得てください。
6. **画面と文書が違うときは推測しない**：プラットフォームの管理画面は変わります。先に公式ドキュメントを確認するか、ユーザーにスクリーンショットをもらってから次の手順を決めてください。
7. **`data/` を削除しない**：本番データが入っています。`git clean -x` のように無視ファイルを消すコマンドは実行しないでください。
8. **用途が合わないときは止まる**：クライアントのアカウント運用代行、複数の別会社ブランドの管理、他人への登録開放を望む場合は、サポート対象外でありプラットフォームの規定に反する可能性があること（コンプライアンスの注意事項を参照）を説明し、続けるかどうかをユーザーに決めてもらいます。

## ステージ 0：用途の確認と準備

まずユーザーに次のことを聞いてください。答えによって後の手順が決まります：

- ブランド名は？管理者の作成時に一緒に作成され（ワークベンチは単一ブランドのみ対応）、レポート、通知、AI プロンプトで使われます。
- どのプラットフォームを管理しますか？Facebook ページ、Instagram、Threads、YouTube、TikTok のうち一部だけでもかまいません。
- それらは**ユーザー自身の**（または自社ブランドの）アカウントですか？
- プライバシーポリシーと利用規約を載せる自分のウェブサイトはありますか？各プラットフォームが公開 URL を求めます。なければ、まず簡単なページを用意する必要があります。
- AI 機能（アイデア出し、台本作成、コメント分類）を使いますか？どの会社の API を使いますか？
- LINE による緊急コメント通知は必要ですか？

## ステージ 1：環境のインストール

現在は **Windows** のみ対応です（起動スクリプトは PowerShell）。次のソフトを確認してインストールし、入っているものは飛ばします：

| ソフト | 用途 | 確認方法 |
|---|---|---|
| Git | コードのダウンロード | `git --version` |
| uv | Python 3.13 とバックエンドのパッケージ管理 | `uv --version` |
| Node.js（LTS） | フロントエンドのビルド、接続ゲートウェイの実行 | `node --version`、`npm --version` |
| 7-Zip | 暗号化バックアップ | `C:\Program Files\7-Zip\7z.exe` がある |
| ngrok | プラットフォームの Webhook を受ける公開入口（起動に必須） | `ngrok version` |
| Tailscale | ワークベンチに内部 HTTPS アドレスを与える。プラットフォームの認可コールバックや他の端末からの接続に使う | `tailscale version` |

**ユーザー本人が行うこと**：ngrok に登録して authtoken をコピーする、Tailscale に登録してログインする。どちらのアカウントも本人が作成し、あなたは手順の説明だけを行います。

Windows は既定で `.ps1` スクリプトの実行を禁止していることがあります（エラーに「実行ポリシー」や execution policy と出ます）。システムの実行ポリシーは変更せず、`powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-all.ps1` のようにその回だけ回避して実行してください。他の `.ps1` も同様です。

## ステージ 2：コードの取得と `.env` の作成

1. コードをダウンロード：`git clone <repo の URL>` を実行してフォルダーに入ります。
2. 設定ファイルをコピー：`.env.example` を `.env` にコピーします。
3. パス関係の設定（`DATABASE_PATH`、`EXPORT_ROOT`、`LOG_PATH`、`PUBLISH_MEDIA_ROOT`）は**空欄のままでかまいません**。プロジェクト内の `data/` が使われます。
4. ユーザーに ngrok の authtoken を `.env` の `NGROK_AUTHTOKEN=` の後ろに貼ってもらいます。
5. 暗号化マスターキーを生成（プラットフォームのキーはこれで暗号化して保存されます）。`backend` フォルダーで次を実行：
   ```bash
   uv run python ../scripts/initialize_ai_encryption.py
   ```
   `ACCOUNT_ENCRYPTION_KEY` が自動で書き込まれ、値は表示されません。ユーザーに伝えてください：**`.env` は別の安全な場所にもバックアップすること**。マスターキーをなくすと、暗号化済みのプラットフォームのキーは読み出せなくなります。
6. バックアップ設定（推奨）：`BACKUP_LOCAL_ROOT`（ローカルのフォルダー）、`BACKUP_DRIVE_ROOT`（たとえばパソコン版 Google ドライブのフォルダー）、`BACKUP_PASSWORD`（ユーザーに長いパスワードを決めて自分で貼ってもらう）。
7. `.env` の `*_INITIAL_PASSWORD` は**入力不要**です。テストデータ専用です。

## ステージ 3：初回起動と管理者の作成

1. パッケージをインストールしてデータベースを作成（`backend` で）：
   ```bash
   uv sync
   uv run alembic upgrade head
   ```
2. ポートの確認：`Get-NetTCPConnection -LocalPort 8000 -State Listen -ErrorAction SilentlyContinue` で 8000 が使われていないか調べます。ユーザーが自分のウィンドウで `start-all.ps1` を実行した場合、初回起動時にポートが使用中なら代わりのポートを尋ねますが、あなた（エージェント）のシェルには対話入力がないため、スクリプトは尋ねずに止まります。使用中なら先にユーザーにどのポートを使うか（たとえば 8010）を聞き、`.env` の `BACKEND_INTERNAL_URL` と `APP_ORIGIN` のローカルアドレスを同じポートに書き換えてください。以下の 8000 はそのポートに読み替えます。
3. 起動（プロジェクトのルートに戻って）：
   ```bash
   ./scripts/start-all.ps1
   ```
   フロントエンドのパッケージのインストール、画面のビルド、バックエンドと Webhook ゲートウェイの起動を自動で行います。<http://127.0.0.1:8000> を含む起動完了メッセージが出れば成功です。
   **注意**：スクリプトはバックエンドと Webhook ゲートウェイを独立プロセス（`Win32_Process`）として起動するので、あなた（エージェント）のバックグラウンドジョブや一時的なシェルが終わってもサービスは止まりません。独立プロセスとして起動できなかったという警告が出た場合は通常起動に戻っており、サービスがあなたのジョブにひも付いたままかもしれません。その場合はユーザーに自分の PowerShell ウィンドウで実行し直してもらってください。起動後は `http://127.0.0.1:8000/api/health` をポーリングして確認します。失敗した場合は、エラーメッセージが `.runtime/` のどのログを見るべきかを示すので、それを読んでください。
4. ワークベンチを動かしているパソコンのブラウザーで、ユーザーに `http://127.0.0.1:8000` を開いてもらいます。新規のデータベースでは「管理者を作成」が表示されるので、ユーザー本人が管理者のユーザー名、パスワード（12〜128 文字。他のサイトと使い回さない長いパスフレーズを推奨）、ブランド名を入力し、「作成してログイン」を押します。パスワードはあなたを経由させないでください。ブランドがないとプラットフォームを連携してもアカウントが登録されず、投稿やデータの画面も使えないので、ブランドは必ず入力してください。この画面はローカルアドレスでのみ使えます。他の端末や Tailscale のアドレスから開くと「ホストのパソコンでセットアップしてください」と表示されます。
   ブラウザーが使えない場合の代替手段：ユーザー自身の対話型ターミナル（`backend` フォルダー）で `uv run python ../scripts/set_password.py <ユーザー名> --create-admin --brand "<ブランド名>"` を実行してもらいます。
5. 確認：`./scripts/check_runtime.ps1` がすべて成功すること。

## ステージ 4：Tailscale の内部 HTTPS を設定

1. ユーザーが Tailscale にログインしていることを確認します。
2. プロジェクトのルートで `node scripts/tailscale.mjs configure` を実行すると、内部 HTTPS アドレスが `.env` に書き込まれます。
3. 再起動：`./scripts/start-all.ps1 -Restart`。
4. 内部アドレス（`https://<デバイス>.<ネットワーク>.ts.net`）を控えておきます。後でプラットフォームの認可コールバックを設定するときに使います。

## ステージ 5：プライバシーポリシーと利用規約

1. [`templates/`](templates) のテンプレートをもとに、**ユーザーの実際の設定に合わせて** 2 ページを下書きします：連携するプラットフォーム、使う AI サービス、`COMMENT_RETENTION_DAYS` の日数、連絡先メール。使わない段落は削除し、他人のポリシーをそのまま写さないでください。
2. ユーザーが内容を確認したら、本人のウェブサイトに掲載して公開 URL を 2 つ用意します。
3. アプリ名にはプラットフォーム名を含められません（たとえば「私の TikTok ツール」は不可）。ウェブサイト名やブランド名がおすすめです。

## ステージ 6：プラットフォームの連携

まずユーザーが正しい種類のアカウントを持っているか確認し、なければ用意してもらいます：

| プラットフォーム | 必要なアカウント |
|---|---|
| Facebook | **Facebook ページ**。Meta API は個人プロフィールを読み書きできないため、ワークベンチはページのみ連携します |
| Instagram | **プロアカウント**（クリエイターまたはビジネス。IG アプリの設定で無料で切り替え可能）で、**上の Facebook ページと連携済み**であること。ワークベンチはページ経由で IG アカウントを見つけるため、通常の個人 IG は連携できません |
| Threads | 個人アカウントで可 |
| YouTube | チャンネルのある Google アカウント |
| TikTok | 個人アカウントで可。Sandbox の Target Users に追加します |

どのプラットフォームも流れは同じです：**ユーザーがプラットフォームの開発者向け管理画面でアプリを作成 → キーをワークベンチに入力 → ワークベンチで「〇〇 アカウントを連携」を押し、プラットフォーム側で認可に同意**。あなたがブラウザーを操作できる場合は、[`エージェント向けプラットフォーム連携ガイド.md`](エージェント向けプラットフォーム連携ガイド.md)（エージェント向けプラットフォーム連携ガイド）に従って開発者向け管理画面の設定を代わりに入力できます。ただしその範囲内で行い、ログイン、シークレット、認可、審査申請は代行しません。ワークベンチの「設定 → プラットフォーム連携」の各カードには「設定ガイド」ボタンがあり、入力するコールバック URL を表示するのでそのままコピーできます。詳しい手順は [`デプロイと運用.md`](デプロイと運用.md) の該当セクションをご覧ください。

| プラットフォーム | ユーザーが管理画面で行うこと | ポイント |
|---|---|---|
| Meta（FB／IG） | Meta for Developers でアプリを作成し、Facebook ログインを追加。コールバックは `<内部アドレス>/api/oauth/meta/callback`。基本設定にポリシーの URL を入力 | 自分で使うだけなら標準アクセスで足り、審査は不要。連携する人はアプリ上のロールが必要 |
| Threads | 同じ Meta アプリに Threads API のユースケースを追加。コールバックは `<内部アドレス>/api/oauth/threads/callback`。自分の Threads アカウントをテスターに追加して招待を承認 | 独自のアプリ ID とシークレットがある |
| YouTube | Google Cloud でプロジェクトを作成し、YouTube Data API v3 と YouTube Analytics API を有効化、ウェブアプリケーションのクライアントを作成。コールバックは `<内部アドレス>/api/oauth/youtube/callback` | 同意画面の公開ステータスを**本番環境**にしないと 7 日ごとに再連携が必要。認可時の「確認されていないアプリ」の警告では「詳細 → 移動」を押す |
| TikTok | TikTok for Developers でアプリを作成し、Sandbox に Login Kit と Content Posting API（Direct Post はオフ）を追加。Scopes は `user.info.basic`、`user.info.stats`、`video.list`、`video.upload`、コールバックは `<内部アドレス>/api/oauth/tiktok/callback`、Target Users に自分のアカウントを追加 | 動画は受信トレイの下書きにしか送れず（24 時間で保留中は最大 5 本）、キャプションはアプリ内で貼り付けます。アプリで投稿するときは公開範囲を「全員」にし、投稿後にログインしていないブラウザーで公開されていることを確認します。Sandbox の App name はウェブサイト名かブランド名にし、TikTok を含めないこと。Production の審査は申請しないでください。TikTok は個人用や自分用のツールを受け付けていません |

キーとシークレットはユーザー本人にワークベンチのカードへ貼ってもらいます（暗号化して保存されます）。会話には貼らないでください。連携後、カードにアカウント名と「連携済み」が表示されます。

**Meta コメント Webhook（任意）**：プラットフォーム連携画面の「Webhook」カードに ngrok の公開 URL と Meta のコメント通知 URL が表示され、「設定ガイド」に手順がすべて載っています。設定しなくても、ワークベンチは 1 時間ごとに自分で取得します（反映が遅くなるだけです）。

## ステージ 7：AI と通知（任意）

- **AI サービス**：管理者がワークベンチの「設定 → AI → 基本」でプロバイダー（Gemini、OpenAI、Anthropic）を選び、API キーを入力して検証します（暗号化して保存）。Gemini API の無料枠は送信内容をモデルの学習に使うため、先に Google Cloud プロジェクトに請求先を設定し、`.env` の `GEMINI_PAID_TIER` を `true` にしてください。そうしないとワークベンチは Gemini にプラットフォームのデータを処理させません。ユーザーがワークベンチに接続するエージェントが個人向けサブスクリプション（Claude Pro／Max、ChatGPT Plus など）でログインしている場合は、そのサービスのプライバシー設定で会話を学習に使う設定をオフにするよう伝えてください。API キーを使うエージェントなら不要です。
- **jev によるコメント分類**：jev は TypeSafe の判定モデルで、コメントをすばやく分類します。「設定 → プラットフォーム連携 → jev」カードの「設定ガイド」に従ってキーを貼り、「接続テスト」を押します。
- **LINE 通知**：「設定 → プラットフォーム連携 → LINE 通知」カードの「設定ガイド」に従います。LINE 公式アカウントを作成して Messaging API を有効にし、Channel secret と Channel access token をカードに貼り、Webhook URL にカードに表示されたアドレスを入力します（先に ngrok の公開 URL が必要）。公式アカウントをグループに招待してメッセージを 1 件送り、「設定 → ワークスペース → 通知 → LINE グループ通知」でグループを選んでブランド通知を有効にし、最後に「接続テスト」を押します。Push には月間の上限があります。

## ステージ 8：日常運用の設定

1. **毎日のバックアップ**：`./scripts/install-backup-task.ps1` で毎日のタスクを登録し、`./scripts/backup.ps1` を手動で 1 回実行して成功を確認します。
2. **データの保持**：まず削除される件数をプレビュー（読み取りのみ）`uv run --project backend python scripts/data_retention.py` し、ユーザーに確認してから `--enable` を付けて毎日の削除を有効にします。
3. **PC 起動時に自動起動**（任意）：管理者が「設定 → ワークスペース」で「PC 起動時に自動起動」をオンにします。
4. **投稿のマスタースイッチ**：投稿画面右上の「投稿をオン」は既定でオフです。オンにするかどうかはユーザー自身が決め、自分で押します。
5. **ブランドのルール**：「設定 → ワークスペース → ブランドテンプレート」でテーマ、NG ワード、ブランドのプロンプトを設定します。AI とエージェントは執筆時に NG ワードを守ります。ワークスペース名（製品の表示名）もワークスペースの設定にあります。
6. **メンバー**（任意）：管理者が「設定 → メンバー」でメンバーを追加し、ロールとブランドを割り当てます。カスタムロールを作り、ロールごとに使える機能を選ぶこともできます。仮パスワードは一度しか表示されず、ユーザー本人が手渡しします。あなたは扱わないでください。他のメンバーは同じ Tailscale ネットワークに参加しないと接続できません。
7. **画面の言語**：ログイン画面と「設定 → マイアカウント」で 繁體中文、English、简体中文、日本語 を切り替えられます。

## ステージ 9：エージェントをワークベンチに接続（任意）

ワークベンチは MCP インターフェースを提供しており、エージェントがテーマ、台本、投稿の下書きを手伝えます。ユーザーに**内部 https アドレス**（ステージ 4）でワークベンチを開いてもらい、「設定 → マイアカウント → Agent をインストール」で Claude Code、Codex、Claude デスクトップ版のいずれかを選び、画面の指示に従ってインストールします。Claude Code の plugin marketplace は https アドレスしか受け付けません。初回利用時は自分のワークベンチアカウントでログインして承認します。リモート MCP に対応した他のエージェントは接続トークンで接続できます。[README](../../README_ja.md) の「エージェントでワークベンチを操作する（MCP）」をご覧ください。詳細は [`デプロイと運用.md`](デプロイと運用.md) の「Agent 接続」にあります。投稿は必ず 2 段階で、エージェントが明細を用意してユーザーに見せ、ユーザーがはっきり同意してから送信します。

## 困ったとき

- 起動に失敗する：エラーメッセージが `.runtime/` のログを示すので、最後の数行を読んでから判断します。よくある原因はポートの使用中、ngrok の authtoken の未入力、パッケージの未インストールです。`NGROK_AUTHTOKEN` がないとスクリプトは最初の手順で止まります。ポート 8000 や 4040 が使用中なら、`Get-NetTCPConnection -LocalPort 8000` でどのプロセスか確認します。別のワークベンチなら、そのフォルダーで `./scripts/stop-all.ps1` を実行してください。知らないプロセスを勝手に終了しないでください。
- フロントエンドのビルドで `Type 'number' is not assignable to type 'Timeout'` のような型エラーが出る：たいてい上位のフォルダー（たとえばユーザーのホームフォルダー）に別のプロジェクトが残した `node_modules/@types/node` があります。現在のバージョンではこの問題を避けていますが、それでも起きる場合はエラーメッセージをメンテナーに報告し、ユーザーのファイルは削除しないでください。
- プラットフォームの連携に失敗する：まずカードのエラー説明を読み、`デプロイと運用.md` と `プラットフォームポリシー.md` と照らし合わせます。権限名やコールバック URL の不一致が最も多い原因です。
- 管理者パスワードを忘れた：リカバリーコードがあれば、ログイン画面の「パスワードをお忘れですか？」から再設定します。なければ [`デプロイと運用.md`](デプロイと運用.md) の「メンバー管理とアカウントの復旧」に従ってホストでコマンドを実行します。
