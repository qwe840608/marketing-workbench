# 自架者合規須知

> **語言 / Language / 语言 / 言語**：繁體中文 | [简体中文](../cn/合规须知.md) | [English](../en/compliance-notes.md) | [日本語](../jp/コンプライアンスの注意事項.md)

自架這個工作檯，你就是自己那組 Meta、Google、TikTok 應用程式的**開發者**。各平台條款的義務落在你身上，不在本專案。這份清單整理自架前後必須自己完成的事；每條規定的出處與查證日期見 [`平台政策.md`](平台政策.md)。

> 這份文件整理的是平台規定與工作檯的對應做法，不是法律意見。條款會改版，以官方最新文件為準。

## 先確認用途：只給自己或自有品牌使用

工作檯的設計前提是**一個品牌、由品牌擁有者自己架設、管理自己的帳號**。以下用途不在支援範圍，也可能違反平台規定：

- **代操**：替客戶或其他公司管理他們的帳號。Meta 要讓沒有應用程式角色的人使用，必須通過 App Review 取得進階存取權限並完成商家驗證；TikTok 明列不接受「幫你或團隊管理的帳號上傳內容的工具」。
- **多品牌**：同一套工作檯管理不同主體（不同公司）的品牌。目前不支援。
- **公開服務**：開放其他人註冊使用。

同一個品牌的團隊成員各自登入工作檯沒有問題：平台只認「誰授權了應用程式」，那個人要在你的 Meta 應用程式上有角色（管理員、開發者或測試人員）。應用程式要建在擁有品牌的那個主體名下：個人品牌用個人帳號，公司品牌由公司建立，不要用員工個人的開發者帳號。

## 1. 隱私權政策與服務條款（每個平台都要）

在你自己的網站放兩個公開頁面，再把網址填進各平台後台。範本在 [`templates/`](templates)：把 `{{…}}` 換成你的資料，刪掉你沒有用到的段落。也可以把範本、你的 `.env` 設定與這份須知交給你自己的 AI，請它依實際設定撰寫。

政策內容必須照實寫你的設定，至少包含：

- 取得哪些資料：自己帳號的貼文與成效、**別人在你貼文下的公開留言**（名稱、帳號識別碼、內容）。
- 委託處理者：TypeSafe（留言分類）、你設定的 AI 服務、你連接的 AI Agent、LINE（緊急通知）。沒用到的就刪掉。
- 保存期限：留言自取得起 `COMMENT_RETENTION_DAYS` 天（預設 365）；YouTube 資料 30 天規則。
- 刪除請求：留言者可要求刪除，7 天內處理。
- YouTube 規定的內容：說明使用 YouTube API 服務、附 [Google 隱私權政策](https://policies.google.com/privacy) 與撤銷授權頁 `https://security.google.com/settings/security/permissions`。
- 服務條款要寫明「使用者同意受 [YouTube 服務條款](https://www.youtube.com/t/terms) 約束」。

## 2. 各平台後台設定

### Meta（Facebook／Instagram／Threads）

- 應用程式名稱不能包含平台名稱，也不要讓人誤以為與 Meta 合作。
- 「基本資料」填隱私權政策網址、服務條款網址與資料刪除說明網址（例如 `/privacy#delete`）。
- 只給自己用時，**一般存取權限**就夠，不需要 App Review；去授權的人必須在應用程式上有角色。Threads 帳號要加為測試人員並在 Threads 接受邀請。
- 只有一般存取權限時收不到 Instagram 留言 Webhook（需要 Live 模式＋進階存取權限）；工作檯會改用定期 API 讀取，不影響使用。
- 權限超過 28 天沒用到，Meta 可能停用該權限。

### Google（YouTube）

- 同意畫面發佈狀態要改成**正式版（In production）**。維持「測試中」時 refresh token 7 天就失效，YouTube 每週都要重新連結。
- 個人使用、100 人以下不需要送 Google 驗證；授權時會看到「未經驗證的應用程式」警告，點「繼續」即可。超過 100 人才必須驗證。
- 「品牌塑造」填應用程式首頁、隱私權政策與服務條款網址。
- 工作檯只要求 `youtube.readonly`、`yt-analytics.readonly`、`youtube.upload`，不要自行加更廣的範圍。

### TikTok

- 應用程式名稱**不能有「TikTok」**，要與你的網站名稱一致，不能只描述功能。
- 工作檯只能用 **Sandbox**：影片以草稿送進你的 TikTok（收件匣通知），你在 App 內補文案並按發佈。收件匣 API 不收文案，也不能選封面。
- Sandbox 的官方定位是測試環境（最多 10 個目標帳號）。長期當正式用途沒有明文允許，屬灰色地帶，請自行評估。
- 直接發佈（`video.publish`）未審核時只能「僅自己可見」，而且發文帳號必須是私人帳號；審核不接受管理自己帳號的工具。讀留言需要以公司身分申請 TikTok API for Business，工作檯不讀 TikTok 留言。
- 介紹工具時用功能描述（例如「用官方 API 送到 TikTok 草稿」），不要說成與 TikTok 合作或受其認可。

### LINE

- 只用於通知你自己的群組；Push 訊息有月額度，先確認方案。

## 3. AI 與資料處理者

- 送到雲端模型的文字會先經 `redact.py` 遮蔽個資，不要關掉。
- **Gemini 只能用付費層**：Gemini API 的免費層會拿送入的內容改善 Google 產品，違反 Meta 對服務供應商的要求。所以工作檯預設不讓 Gemini 處理平台資料，Google Cloud 專案綁定帳單後才設 `GEMINI_PAID_TIER=true`。Anthropic、OpenAI 的 API 預設不拿 API 資料訓練，不用另外設定。
- **用個人訂閱登入的 Agent 要關閉訓練**：Agent 透過 MCP 讀到的留言會進到對話裡。Agent 若用個人訂閱登入（例如 Claude Pro／Max 上的 Claude Code、ChatGPT Plus），到該服務的隱私設定關閉「用對話訓練模型」；Agent 用 API 金鑰就不必（Gemini 仍須付費層）。
- Meta 要求服務供應商以**書面**同意只依你的指示處理資料。需要時向 TypeSafe 等供應商索取資料處理協議（DPA）。

## 4. 部署後要做的事

1. 預覽資料保留會刪除多少筆（只讀）：`uv run --project backend python scripts/data_retention.py`。
2. 確認後啟用每日刪除：同一個指令加 `--enable`。
3. 收到留言者的刪除請求：用 `--find-commenter` 找到人，再用 `--delete-contact` 預覽，確認後加 `--apply` 刪除。
4. 「中斷連結」會撤銷授權並刪除該平台已同步的資料（YouTube、TikTok），平台上的內容不受影響。
5. 工作檯介面只開放本機與私人網路（Tailscale），不要把介面直接放上公開網路；公開入口只有驗簽的 Webhook 與限時媒體連結。
6. 發生資安事件（電腦或帳號被入侵）時，先中斷各平台連結並更換金鑰；TikTok 條款要求立即中斷連線並回報。

## 5. 開源授權與 TikTok

工作檯只透過 HTTP 呼叫各平台官方 API，不內含 TikTok 的 SDK 或範例程式碼，所以 TikTok 開發者條款 III.3.e（不得讓 TikTok 開發者服務受開源授權義務約束）不會因為本專案的授權而受影響。如果你在自己的分支加進平台的 SDK，請自行檢查授權相容性。
