# 領域文件

> **語言 / Language / 语言 / 言語**：繁體中文 | [简体中文](../../cn/agents/领域文档.md) | [English](../../en/agents/domain.md) | [日本語](../../jp/agents/ドメインドキュメント.md)

工程類 skill 在探索程式碼庫時，應該如何使用這個 repo 的領域文件。

## 探索前先讀這些

- repo 根目錄的 **`CONTEXT.md`**，或
- repo 根目錄若有 **`CONTEXT-MAP.md`**：它會指向每個情境各自的 `CONTEXT.md`。和主題相關的每一份都要讀。
- **`docs/adr/`**：讀和你即將動到的範圍有關的 ADR。多情境的 repo 還要看 `src/<context>/docs/adr/` 裡屬於該情境的決策。

以上檔案不存在時，**直接略過、不用提**。不要指出它們不存在，也不要一開始就建議建立。`/domain-modeling` skill（經由 `/grill-with-docs` 與 `/improve-codebase-architecture` 觸發）會在術語或決策真正定案時才建立它們。

## 檔案結構

單一情境的 repo（大多數 repo）：

```
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-event-sourced-orders.md
│   └── 0002-postgres-for-write-model.md
└── src/
```

多情境的 repo（根目錄有 `CONTEXT-MAP.md`）：

```
/
├── CONTEXT-MAP.md
├── docs/adr/                          ← system-wide decisions
└── src/
    ├── ordering/
    │   ├── CONTEXT.md
    │   └── docs/adr/                  ← context-specific decisions
    └── billing/
        ├── CONTEXT.md
        └── docs/adr/
```

## 使用術語表的用詞

輸出內容提到領域概念時（議題標題、重構提案、假設、測試名稱），使用 `CONTEXT.md` 定義的術語。不要改用術語表明確避免的同義詞。

需要的概念還不在術語表裡，代表兩種情況之一：你在發明專案沒在用的說法（重新考慮），或是真的有缺口（記下來交給 `/domain-modeling`）。

## 標出與 ADR 的衝突

輸出內容與既有 ADR 矛盾時，要明確指出，不要默默推翻：

> _與 ADR-0007（event-sourced orders）矛盾，但值得重新討論，因為……_
