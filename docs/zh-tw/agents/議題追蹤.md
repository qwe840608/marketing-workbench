# 議題追蹤：GitHub

> **語言 / Language / 语言 / 言語**：繁體中文 | [简体中文](../../cn/agents/议题跟踪.md) | [English](../../en/agents/issue-tracker.md) | [日本語](../../jp/agents/Issueトラッカー.md)

本 repo 的議題與規格都記在 GitHub issues。所有操作都用 `gh` CLI。

## 慣例

- **建立議題**：`gh issue create --title "..." --body "..."`。多行內文用 heredoc。
- **讀取議題**：`gh issue view <number> --comments`，用 `jq` 篩選留言，並一併取得標籤。
- **列出議題**：`gh issue list --state open --json number,title,body,labels,comments --jq '[.[] | {number, title, body, labels: [.labels[].name], comments: [.comments[].body]}]'`，搭配適當的 `--label` 與 `--state` 篩選。
- **在議題留言**：`gh issue comment <number> --body "..."`
- **加上／移除標籤**：`gh issue edit <number> --add-label "..."` / `--remove-label "..."`
- **關閉**：`gh issue close <number> --comment "..."`

repo 從 `git remote -v` 判斷；在 clone 裡執行時 `gh` 會自動判斷。

## 把 PR 當作分類來源

**把 PR 當作需求來源：否。** _（若這個 repo 把外部 PR 視為功能需求，改成 `yes`；`/triage` 會讀這個設定。）_

設為 `yes` 時，PR 和議題走同一套標籤與狀態，改用對應的 `gh pr` 指令：

- **讀取 PR**：`gh pr view <number> --comments`，差異用 `gh pr diff <number>`。
- **列出待分類的外部 PR**：`gh pr list --state open --json number,title,body,labels,author,authorAssociation,comments`，只保留 `authorAssociation` 為 `CONTRIBUTOR`、`FIRST_TIME_CONTRIBUTOR` 或 `NONE` 的（去掉 `OWNER`/`MEMBER`/`COLLABORATOR`）。
- **留言／標籤／關閉**：`gh pr comment`、`gh pr edit --add-label`/`--remove-label`、`gh pr close`。

GitHub 的議題與 PR 共用同一組編號，所以單獨的 `#42` 可能是兩者之一：先用 `gh pr view 42` 判斷，失敗再用 `gh issue view 42`。

## skill 說「發佈到議題追蹤」時

建立一個 GitHub issue。

## skill 說「取得相關票」時

執行 `gh issue view <number> --comments`。

## Wayfinding 操作

供 `/wayfinder` 使用。**map** 是單一議題，**child** 議題是各張票。

- **Map**：一個標上 `wayfinder:map` 的議題，內文放 Notes／Decisions-so-far／Fog。`gh issue create --label wayfinder:map`。
- **Child 票**：以 GitHub 子議題（sub-issue，用 `gh api` 呼叫 sub-issues 端點）連到 map 的議題。沒有啟用子議題時，把 child 加進 map 內文的任務清單，並在 child 內文開頭寫 `Part of #<map>`。標籤：`wayfinder:<type>`（`research`/`prototype`/`grilling`/`task`）。認領後指派給負責的開發者。
- **阻擋關係**：使用 GitHub **原生的議題相依（issue dependencies）**，這是標準、在介面上看得到的表示法。新增關係用 `gh api --method POST repos/<owner>/<repo>/issues/<child>/dependencies/blocked_by -F issue_id=<blocker-db-id>`，其中 `<blocker-db-id>` 是阻擋者的數字 **database id**（`gh api repos/<owner>/<repo>/issues/<n> --jq .id`，_不是_ `#number` 或 `node_id`）。GitHub 會回報 `issue_dependencies_summary.blocked_by`（只算未關閉的阻擋者，也就是即時的關卡）。不支援相依時，改在 child 內文開頭寫一行 `Blocked by: #<n>, #<n>`。所有阻擋者都關閉後，這張票就解除阻擋。
- **前線查詢**：列出 map 底下未關閉的 child（`gh issue list --state open`，範圍限 map 的子議題／任務清單），去掉有未關閉阻擋者（`issue_dependencies_summary.blocked_by > 0`，或 `Blocked by` 行裡有未關閉的議題）或已有指派人的；照 map 順序取第一張。
- **認領**：`gh issue edit <n> --add-assignee @me`，這是該 session 的第一個寫入動作。
- **結案**：`gh issue comment <n> --body "<answer>"`，再 `gh issue close <n>`，然後在 map 的 Decisions-so-far 補一行脈絡指標（摘要＋連結）。
