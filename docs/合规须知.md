# 自托管者合规须知

> **语言 / Language / 語言 / 言語**：[繁體中文](合規須知.md) | 简体中文 | [English](compliance-notes.md) | [日本語](コンプライアンスの注意事項.md)

自行部署这个工作台，你就是自己那组 Meta、Google、TikTok 应用的**开发者**。各平台条款规定的义务落在你身上，而不在本项目。这份清单整理了自托管前后必须自己完成的事；每条规定的出处与核实日期见 [`平台政策与API限制.md`](平台政策与API限制.md)（平台政策）。

> 这份文档整理的是平台规定与工作台的对应做法，不是法律意见。条款会更新，以官方最新文档为准。

## 先确认用途：只供自己或自有品牌使用

工作台的设计前提是**一个品牌、由品牌所有者自己部署、管理自己的账号**。以下用途不在支持范围内，也可能违反平台规定：

- **代运营**：替客户或其他公司管理他们的账号。Meta 要让没有应用角色的人使用，必须通过 App Review 取得高级访问权限并完成商家验证；TikTok 明确列出不接受“帮你或团队管理的账号上传内容的工具”。
- **多品牌**：同一套工作台管理不同主体（不同公司）的品牌。目前不支持。
- **公开服务**：开放给其他人注册使用。

同一个品牌的团队成员各自登录工作台没有问题：平台只认“谁授权了应用”，那个人要在你的 Meta 应用上有角色（管理员、开发者或测试人员）。应用要创建在拥有品牌的那个主体名下：个人品牌用个人账号，公司品牌由公司创建，不要用员工个人的开发者账号。

## 1. 隐私政策与服务条款（每个平台都需要）

在你自己的网站上放两个公开页面，再把网址填进各平台后台。模板在 [`templates/`](templates/)：把 `{{…}}` 换成你的信息，删掉你没有用到的段落。也可以把模板、你的 `.env` 设置与这份须知交给你自己的 AI，请它按实际设置撰写。

政策内容必须如实写明你的设置，至少包含：

- 获取哪些数据：自己账号的帖子与效果数据、**别人在你帖子下的公开评论**（名称、账号标识符、内容）。
- 受托处理方：TypeSafe（评论分类）、你设置的 AI 服务、你连接的 AI Agent、LINE（紧急通知）。没用到的就删掉。
- 保存期限：评论自获取起 `COMMENT_RETENTION_DAYS` 天（默认 365）；YouTube 数据的 30 天规则。
- 删除请求：评论者可要求删除，7 天内处理。
- YouTube 规定的内容：说明使用了 YouTube API 服务，附上 [Google 隐私政策](https://policies.google.com/privacy) 与撤销授权页 `https://security.google.com/settings/security/permissions`。
- 服务条款要写明“用户同意受 [YouTube 服务条款](https://www.youtube.com/t/terms) 约束”。

## 2. 各平台后台设置

### Meta（Facebook／Instagram／Threads）

- 应用名称不能包含平台名称，也不要让人误以为与 Meta 有合作。
- “基本”中填写隐私政策网址、服务条款网址与数据删除说明网址（例如 `/privacy#delete`）。
- 只供自己使用时，**标准访问权限**就够了，不需要 App Review；进行授权的人必须在应用上有角色。Threads 账号要添加为测试人员，并在 Threads 中接受邀请。
- 只有标准访问权限时收不到 Instagram 评论 Webhook（需要 Live 模式＋高级访问权限）；工作台会改用定期 API 读取，不影响使用。
- 权限超过 28 天未使用，Meta 可能停用该权限。

### Google（YouTube）

- 同意屏幕的发布状态要改为**正式版（In production）**。保持“测试”状态时 refresh token 7 天就失效，YouTube 每周都要重新连接。
- 个人使用、100 人以下不需要提交 Google 验证；授权时会看到“未经验证的应用”警告，点击“继续”即可。超过 100 人才必须验证。
- “品牌塑造”中填写应用首页、隐私政策与服务条款网址。
- 工作台只请求 `youtube.readonly`、`yt-analytics.readonly`、`youtube.upload`，不要自行添加范围更广的权限。

### TikTok

- 应用名称**不能包含“TikTok”**，要与你的网站名称一致，不能只描述功能。
- 工作台只能使用 **Sandbox**：视频以草稿形式发送到你的 TikTok（收件箱通知），你在 App 内补上文案并点击发布。收件箱 API 不接收文案，也不能选择封面。
- Sandbox 的官方定位是测试环境（最多 10 个目标账号）。长期作为正式用途并没有明文允许，属于灰色地带，请自行评估。
- 直接发布（`video.publish`）未经审核时只能“仅自己可见”，而且发帖账号必须是私密账号；审核不接受管理自己账号的工具。读取评论需要以公司身份申请 TikTok API for Business，工作台不读取 TikTok 评论。
- 介绍工具时用功能描述（例如“用官方 API 发送到 TikTok 草稿”），不要说成与 TikTok 合作或获得其认可。

### LINE

- 只用于通知你自己的群组；Push 消息有月度额度，先确认方案。

## 3. AI 与数据处理方

- 发送到云端模型的文本会先经过 `redact.py` 屏蔽个人信息，不要关闭。
- **Gemini 只能用付费层**：Gemini API 的免费层会用传入的内容改进 Google 产品，违反 Meta 对服务提供商的要求。所以工作台默认不让 Gemini 处理平台数据，Google Cloud 项目绑定结算账号后才设置 `GEMINI_PAID_TIER=true`。Anthropic、OpenAI 的 API 默认不用 API 数据训练，不需要另外设置。
- **用个人订阅登录的 Agent 要关闭训练**：Agent 通过 MCP 读到的评论会进入对话。Agent 如果用个人订阅登录（例如 Claude Pro／Max 上的 Claude Code、ChatGPT Plus），请到该服务的隐私设置中关闭“用对话训练模型”；Agent 使用 API 密钥则不必（Gemini 仍须使用付费层）。
- Meta 要求服务提供商以**书面**形式同意只按你的指示处理数据。需要时向 TypeSafe 等提供商索取数据处理协议（DPA）。

## 4. 部署后要做的事

1. 预览数据保留会删除多少条（只读）：`uv run --project backend python scripts/data_retention.py`。
2. 确认后启用每日删除：同一条命令加上 `--enable`。
3. 收到评论者的删除请求：用 `--find-commenter` 找到这个人，再用 `--delete-contact` 预览，确认后加 `--apply` 删除。
4. “断开连接”会撤销授权并删除该平台已同步的数据（YouTube、TikTok），平台上的内容不受影响。
5. 工作台界面只对本机与私有网络（Tailscale）开放，不要把界面直接暴露到公网；公开入口只有经过签名验证的 Webhook 与限时媒体链接。
6. 发生安全事件（电脑或账号被入侵）时，先断开各平台连接并更换密钥；TikTok 条款要求立即断开连接并报告。

## 5. 开源许可与 TikTok

工作台只通过 HTTP 调用各平台官方 API，不包含 TikTok 的 SDK 或示例代码，所以 TikTok 开发者条款 III.3.e（不得让 TikTok 开发者服务受开源许可义务约束）不会因为本项目的许可而受影响。如果你在自己的分支中加入平台的 SDK，请自行检查许可兼容性。
